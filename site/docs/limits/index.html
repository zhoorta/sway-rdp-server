Limits and status

Waydesk is early, free software, written and tested by one person on real servers. This page says what was tried, what was not, and what to expect. Nothing here is hidden in a footnote elsewhere.

Status

  • Early software. Version 0.4.0. Expect rough edges; open an issue when you find one.
  • Systems: Debian 13 and Ubuntu 26.04, on amd64 and arm64 (the table below). Clean installs of earlier versions passed on both; the 0.4.0 arm64 packages are built but have not been installed on a machine yet.
  • No second factor. The login is the account's password inside TLS: keep the port behind an SSH tunnel or a VPN.
  • Not an audited product. Four internal review passes are written down, with what is still open.

Without a GPU

Everything runs on the CPU. OpenGL and Vulkan applications open and are slow: glxgears, vkcube and Zed opened on a server with no render node. A WebGL page in the browser does not animate, because Waydesk starts Chromium without its GPU process there (it saves memory); with SwiftShader it runs at about 8 fps for a full-screen page, using three of four cores. With a render node but the GPU switched off, vkcube failed to show its window. Blender, Kdenlive, darktable, VS Code and LibreOffice were tried with the GPU on and off on a machine that had one, not on a machine without a render node.

With a GPU

Tried on an Intel HD 630 and an NVIDIA RTX 4000 SFF Ada. NVIDIA needs the vendor's driver, 615 or newer (Debian's 550 cannot draw the desktop). AMD should work through VAAPI and was not tried. The GPU is shared by every session: ten users on full-screen WebGL get about 13 fps each on the HD 630, and an integrated GPU takes some system memory for each session. Not measured: several users on one NVIDIA card (GeForce cards limit simultaneous NVENC sessions; the encoder then falls back to OpenH264) and a card with its own memory under many users. More on the GPU page.

How many users

On an 8 GB, 4-core server count 7 to 8 users with Chromium, Calc and VS Code open if most are idle. A 12-vCPU, 23 GB server (Hetzner CPX52, 123.60 euros a month) held 12 of them before it refused the 13th: memory is the limit, about 1.6 GB per such user. Someone compiling or recalculating needs more, and the server refuses a new session instead of slowing everyone down. The figures and their method are on the measurements page.
