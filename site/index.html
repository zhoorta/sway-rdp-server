A Linux desktop over RDP, out of the box.

One apt install on Debian 13 or Ubuntu 26.04 (amd64 or arm64). Every account that logs in gets its own desktop, with a shell, a dock and its apps, kept alive between connections. No GPU, no client to install: use the Windows App, Remmina or any RDP client.

install–□✕
$ curl -fsSLO https://waydesk.dev/apt/waydesk-repo.deb
$ sudo apt install ./waydesk-repo.deb
$ sudo apt install waydesk
$ sudo waydesk-setup-admin

Free software, early. Tested with FreeRDP and the Windows App on macOS.

Built to stay light and fast

Most of the work is in not wasting what a server has: memory, CPU and a slow link. Every figure has its method under Measurements.

slow or lossy links–□✕

TCP BBR for the connection

On one distant link with about 4 % packet loss the connection went from 0.3 to 2 to 4 Mbit/s, and typed letters stopped arriving in bursts.

One link, one afternoon: method under Measurements.

flow control–□✕

The picture follows the link

Frames and bytes in flight follow the path, and the video bitrate follows what the link delivers, from 300 kbit/s up to the configured 10 Mbit/s. No queue of seconds.

H.264–□✕

Tuned for screens, in software

Screen-content mode, only the changed rectangles, a refinement when the picture stops: about half the bandwidth of the camera mode for moving pictures. No GPU needed.

pointer–□✕

The pointer has no delay

The client draws it, with the real shape (text cursor, resize arrows, hand): it moves at once and only the shape arrives a round trip late.

memory–□✕

Ceilings, compressed swap, a refusal

A memory ceiling per account, idle pages in compressed swap, and a new login refused when the machine is full: 7 to 8 heavy sessions on an 8 GB server.

isolation–□✕

One session per account

Each account in its own session and its own systemd slice. The daemon has no privileges; a small root helper starts sessions as the account.

Your applications run as they are

Wayland or X11, from the distribution or from Flathub: nothing to port.

X11–□✕

X11 applications run

Applications that only speak X11 run through XWayland: one Xwayland server per account, started when the first one opens, and closed to the other accounts. Checked with CoreX Hardware Monitor, xeyes and GIMP.

Flathub–□✕

Flatpak, out of the box

Flathub works as it is. Checked in a session: Chromium, VS Code, LibreOffice Calc, Obsidian, Slack, GNOME Text Editor and GIMP.

windows–□✕

Real windows

Every window has a title bar with minimize, maximize and close, in the colours of the theme (dark or light), and soft shadows. A dock shows what is open and bounces while an application starts.

Connect your way

The port is closed to the network until you open it. waydesk-setup-admin asks how you will connect, and waydesk-admin access changes it later. The details are in docs/ACCESS.md.

this machine or an SSH tunnel–□✕

The default default

The port listens on 127.0.0.1 only. One ssh -L and the client connects to localhost. Nothing to configure.

a trusted local network–□✕

Directly, on a LAN

sudo waydesk-admin access lan opens the port to this server's network and nothing else: the daemon closes every other source address before TLS and before any login. Narrow it further with a list of ranges.

a VPN–□✕

WireGuard in two commands recommended

waydesk-admin vpn init makes the VPN and opens the port to it only; vpn add NAME makes a client, with a QR code. vpn remove cuts a client off at once. Keep the port off the open internet: it is a password login with no second factor.

a certificate clients can verify–□✕

No fingerprint to compare

waydesk-admin cert local-ca makes a certificate authority of your own and a certificate for this server. Each client imports the authority once, then checks every connection. A certificate from Let's Encrypt works too.

Run as an administrator of the server. The port listens on 127.0.0.1 only; see reaching it.

1. Add the repository

One small package: the signing key, the apt source for your release (trixie or resolute, chosen from VERSION_CODENAME) and a pin so these packages win over third-party builds of the same names.

$ curl -fsSLO https://waydesk.dev/apt/waydesk-repo.deb
$ sudo apt install ./waydesk-repo.deb

2. Check the key

This first download cannot be verified by the repository itself. Compare the key you got with this fingerprint (ed25519, expires 2029-10-21):

$ gpg --show-keys --with-fingerprint /usr/share/keyrings/waydesk-archive-keyring.gpg
C646 72B2 5ECD 4773 196C  3958 9D8E 8874 E676 17F4

If it differs, stop and tell us.

3. Install

$ sudo apt update
$ sudo apt install waydesk

Installs the RDP daemon, the root helper, waydesk-admin, our sway build, zram swap and the desktop package. waydesk-server alone is enough for a session with a plain terminal (a minimal sway config ships with it).

4. Shell and first administrator

$ sudo waydesk-setup           # wizard: shell, Chromium, LibreOffice, VS Code, ...
$ sudo waydesk-setup-admin     # the account that logs in over RDP and manages the others

There is no default account and no default password. waydesk-setup-admin prints the certificate fingerprint to expect on the first connection.

Architecture

diagram–□✕

A session is a systemd unit of the account, so it survives a disconnect, sits in user-UID.slice (limits there apply) and is killed with its control group. A second login from the same account takes the running session over. Design notes: docs/MULTIUSER-DESIGN.md in the repository.

Method: one account at a time, 70 s after its last application started, applications left idle (an upper bound for idle load, no figure for active work). The server refuses a session when less than about 1.1 GB is available; the refusal reaches the client as ERRINFO_OUT_OF_MEMORY. One heavy user costs 1.85 GB (Debian) to 2.0 GB (Ubuntu, Flatpak builds of Chromium and VS Code, a 30 MB tree instead of 25 MB).

Compressed swap

zram with zstd compresses this load about 4.5 to 5 : 1 (Ubuntu: 6.6 GB of data in 1.3 GB of RAM at seven users). The package sizes the device like the RAM (at most 16 GiB). With Debian's default of half the RAM, six heavy users fit instead of eight.

Security

access–□✕

Reaching it

Keep the RDP port off the open internet: the login is the account's password inside TLS, with no second factor. It listens on this machine only until you choose otherwise, and the daemon closes every source address that is not allowed before TLS and before any login.

The guide, docs/ACCESS.md, covers:

  • where the port listens and who may connect: this machine, a local network, a VPN, or a list of ranges you choose;
  • a certificate that clients can verify: a local authority made in one command, or one from Let's Encrypt;
  • a WireGuard VPN in two commands, with a client per device and a QR code;
  • what to do if you open the port to the internet anyway.

The threat model and the open items are on GitHub: docs/THREAT-MODEL.md, with the internal reviews in docs/SECURITY-REVIEW.md.

Limits

known limits–□✕
  • Early software. Tested with FreeRDP and the Windows App on macOS; Microsoft Remote Desktop (Windows) and mstsc were not tested.
  • No GPU: applications that insist on one do not start. Zed fails with "Failed to create surface"; VS Code and LibreOffice work.
  • Sizing: on an 8 GB, 4-core server count 7 to 8 users with Chromium, Calc and VS Code open if most are idle. Someone compiling or recalculating needs more, and the server refuses a new session instead of slowing everyone down.

Commands: administration

waydesk-admin status [--json]

memory, swap, load, running sessions and what each account uses

waydesk-admin users list [--json]

accounts that may log in

waydesk-admin users add NAME [--admin] [--sudo] [--no-rdp]

create an account; prints a generated password

waydesk-admin users passwd NAME [--stdin]

set a password (read from stdin, never from an argument)

waydesk-admin users remove NAME [--delete-home]

remove an account

waydesk-admin users enable NAME | disable NAME [--keep-session]

allow or stop RDP logins for an account

waydesk-admin users admin NAME on|off

Flatpak installs without a password

waydesk-admin users sudo NAME on|off

membership of the sudo group

waydesk-admin users limit NAME [show | reset | --memory SIZE] [--swap SIZE] [--cpu-weight N] [--tasks N]

per-account ceilings

waydesk-admin sessions list [--json] | end NAME

running sessions; ending one closes that account's desktop

Commands: setup

waydesk-setup [--list | --check]

choose and install shell, browsers, office, developer and creative apps

waydesk-setup-admin [--name NAME [--password-stdin]] [--existing NAME]

the first administrator: RDP access, panels, Flatpak installs without a password
